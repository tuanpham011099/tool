# Planning: Web App Cắt Ghép Video & Ảnh

## 1. Mục tiêu

Xây dựng web app cho phép người dùng:

- Upload ảnh nền.
- Upload video (dài hoặc ngắn).
- Chọn đoạn video muốn dùng bằng slider có **hai đầu**: Start và End.
- Giới hạn đoạn video được chọn tối đa **30 giây**.
- Bấm **Generate** để ghép video vào **giữa ảnh**.
- Ảnh là nền, video nằm ở giữa; phần trên và dưới của ảnh vẫn hiển thị.
- Tải xuống hoặc xem video kết quả.

## 2. Phạm vi MVP

### Có trong MVP

- Upload ảnh: JPG, PNG, WebP.
- Upload video: MP4, MOV, WebM.
- Lưu file upload và file output trên local server.
- Đọc metadata video: duration, width, height.
- Slider chọn Start và End của video.
- Giới hạn `end - start <= 30` giây.
- Preview video trước khi generate.
- Ghép video vào giữa ảnh bằng FFmpeg.
- Xuất video MP4 H.264 + AAC.
- Xem và tải video kết quả.
- Hiển thị trạng thái job: queued, processing, completed, failed.

### Chưa có trong MVP

- Database.
- Đăng nhập / user management.
- Cloud storage như S3, R2, GCS.
- Redis, Celery, BullMQ.
- Thanh toán.
- Nhiều video trong một ảnh.
- Watermark, text, nhạc nền.
- Chỉnh sửa nâng cao như zoom, rotate, transition.

## 3. Tech stack đề xuất

### Lựa chọn khuyến nghị

**Frontend:** Next.js + React + TypeScript + Tailwind CSS  
**Backend:** FastAPI + Python  
**Media processing:** FFmpeg + FFprobe  
**Storage:** Local disk  
**Job state:** In-memory hoặc JSON file  
**Output:** MP4 H.264 + AAC  

### Lý do chọn FastAPI

- Nhận file upload qua `UploadFile` rất tiện.
- Validation request bằng Pydantic rõ ràng.
- Có `BackgroundTasks` để chạy FFmpeg nền.
- Python phù hợp khi sau này mở rộng media pipeline hoặc AI.
- Frontend vẫn dùng Next.js/React, không bị ràng buộc ngôn ngữ backend.

### Phương án thay thế

| Lựa chọn | Ưu điểm | Nhược điểm | Khi nào nên dùng |
|---|---|---|---|
| Node.js + Express + TypeScript | Một ngôn ngữ cho frontend/backend, chia sẻ type dễ | Media ecosystem yếu hơn Python | Muốn đồng nhất JS/TS |
| NestJS + TypeScript | Cấu trúc rõ, phù hợp dự án lớn | Boilerplate nhiều hơn | Team quen NestJS |
| FastAPI + Python | Rất phù hợp media/AI, code gọn | Cần biết Python | Khuyến nghị cho dự án này |
| Go + Gin/Fiber | Hiệu năng API tốt, memory thấp | Phát triển chậm hơn, overkill cho MVP | Cần scale rất cao |

## 7. Slider chọn Start / End

Slider phải là **dual-range slider**, có hai handle:

- Handle trái: `start`.
- Handle phải: `end`.
- Khoảng cách hai handle: `end - start`.
- Giới hạn: `end - start <= 30`.

### Quy tắc

```text
start >= 0
end <= videoDuration
end > start
end - start <= 30
```

### Trường hợp video ngắn

Nếu `videoDuration <= 30`:

```text
start = 0
end = videoDuration
```

### Trường hợp video dài

Nếu `videoDuration > 30`:

```text
start có thể từ 0 đến videoDuration - 30
end = start + 30
```

Tuy nhiên, UX tốt hơn là cho phép kéo cả hai handle, miễn là:

```text
end - start <= 30
```

### Hành vi khi kéo slider

- Nếu kéo Start vượt quá `end - 30`, tự động đẩy End theo.
- Nếu kéo End vượt quá `start + 30`, tự động đẩy Start theo.
- Khi kéo Start, video preview seek tới `start`.
- Khi kéo End, video preview seek tới `end`.
- Hiển thị realtime:
  - Start
  - End
  - Clip length
  - Cảnh báo nếu vượt 30 giây

### UI slider

```text
Video duration: 02:15

0s          30s         60s         90s        135s
|───────────────[■■■■■■■■■■■■]─────────────────|
              Start: 00:25     End: 00:55
                       Clip length: 00:30
```

## 9. Validation

| Trường | Quy tắc |
|---|---|
| Ảnh | JPG, PNG, WebP |
| Ảnh | Tối đa 20MB |
| Video | MP4, MOV, WebM |
| Video | Tối đa 500MB cho MVP |
| `start` | `start >= 0` |
| `end` | `end <= videoDuration` |
| `end` | `end > start` |
| `end - start` | `<= 30` |
| Video | Phải có stream video hợp lệ |
| Output | MP4 H.264 + AAC |

Không tin MIME type từ browser. Sau khi lưu file, dùng `ffprobe` để xác minh video thực sự decode được.

## 10. Quy tắc layout output

Mặc định dùng chế độ **Cover**:

- Ảnh là nền full khung.
- Video được crop/scale để lấp toàn bộ chiều rộng ảnh.
- Video chỉ chiếm vùng giữa ảnh.
- Phần trên và dưới của ảnh vẫn hiển thị.

### Ví dụ

Ảnh 1080×1920, video gốc 1920×1080:

```text
Ảnh nền: 1080 x 1920
Vùng video: 1080 x 608
Vị trí video: y = (1920 - 608) / 2 = 656
```

```text
┌──────────────────┐
│      ẢNH         │  656px
├──────────────────┤
│      VIDEO       │  608px
├──────────────────┤
│      ẢNH         │  656px
└──────────────────┘
```

### Chế độ hiển thị

| Chế độ | Cách xử lý | Khi nào dùng |
|---|---|---|
| `cover` | Video crop/fill toàn bộ chiều rộng ảnh | Ảnh dọc, video ngang |
| `contain` | Video giữ tỉ lệ, đặt giữa; hai bên có thể còn ảnh nền | Giữ trọn nội dung video |

## 11. FFmpeg command mẫu

Giả sử:

- Ảnh: `background.jpg`, 1080×1920.
- Video: `input.mp4`.
- Start: 25 giây.
- End: 55 giây.
- Duration: 30 giây.
- Chiều cao vùng video: 608px.

```bash
ffmpeg -y \
  -i ./uploads/images/background.jpg \
  -ss 25 -t 30 -i ./uploads/videos/input.mp4 \
  -filter_complex "\"
[1:v]scale=1080:-2,crop=1080:608:0:(ih-608)/2,setsar=1[v];\
[0:v][v]overlay=0:656:format=auto[out]" \\
  -map "[out]" \
  -map 1:a? \
  -c:v libx264 \
  -preset veryfast \
  -crf 20 \
  -c:a aac \
  -b:a 128k \
  ./uploads/outputs/output.mp4
```

### Giải thích

- `-ss 25`: bắt đầu tại giây 25.
- `-t 30`: lấy đúng 30 giây.
- `scale=1080:-2`: scale video về rộng 1080, giữ tỉ lệ và đảm bảo chiều cao chẵn.
- `crop=1080:608:0:(ih-608)/2`: cắt phần giữa video theo chiều dọc.
- `overlay=0:656`: đặt video vào giữa ảnh.
- `libx264` + `aac`: tương thích tốt với hầu hết trình duyệt và thiết bị.

## 15. Danh sách task

### Phase 1 — Setup

- Init monorepo với `web/` và `server/`.
- Setup Next.js + TypeScript + Tailwind.
- Setup FastAPI + Uvicorn.
- Cài FFmpeg và FFprobe.
- Kiểm tra `ffmpeg -version` và `ffprobe -version`.
- Tạo thư mục `uploads/images`, `uploads/videos`, `uploads/outputs`.
- Cấu hình static file serving cho thư mục `uploads`.

### Phase 2 — Upload

- Tạo `POST /api/upload/image`.
- Tạo `POST /api/upload/video`.
- Lưu file vào local disk.
- Sinh `fileId` ngẫu nhiên.
- Validate đuôi file, MIME, dung lượng.
- Chạy `ffprobe` để lấy duration, width, height.
- Trả URL để frontend preview.

### Phase 3 — Frontend

- Tạo UI upload ảnh và video.
- Preview ảnh và video.
- Đọc duration video.
- Xây dựng `VideoTrimSlider` với hai handle.
- Giới hạn `end - start <= 30`.
- Đồng bộ slider với video preview.
- Hiển thị Start, End, Clip length.
- Thêm nút Set Start và Set End.
- Disable Generate khi thiếu file hoặc tham số không hợp lệ.
- Gọi API generate và xử lý loading/error.

### Phase 4 — Render

- Tạo `POST /api/generate`.
- Validate `imageId`, `videoId`, `start`, `end`.
- Tính `duration = end - start`.
- Build FFmpeg command động.
- Chạy FFmpeg bằng `subprocess`.
- Lưu output vào `uploads/outputs/`.
- Trả jobId và trạng thái processing.
- Tạo `GET /api/jobs/{jobId}`.
- Xử lý lỗi FFmpeg và cleanup file tạm nếu cần.

### Phase 5 — Hoàn thiện

- Thêm progress bar.
- Thêm retry job thất bại.
- Giới hạn số FFmpeg chạy đồng thời.
- Tự động xóa file cũ.
- Thêm unit test cho validation.
- Thêm Dockerfile nếu muốn deploy dễ hơn.

## 16. Rủi ro và cách xử lý

| Rủi ro | Giải pháp |
|---|---|
| Video dài làm server chậm | Chạy FFmpeg background, không block API |
| Nhiều user render cùng lúc | Giới hạn concurrent jobs |
| File lớn | Giới hạn dung lượng upload |
| Codec lạ | Chuẩn hóa output MP4 H.264 + AAC |
| File tên trùng hoặc path traversal | Dùng ID ngẫu nhiên, không dùng tên gốc |
| FFmpeg fail | Bắt stderr, log lỗi, trả trạng thái failed |
| Server restart mất job | Lưu job state vào JSON file |
| Browser không hỗ trợ MOV/HEVC | Output luôn MP4 H.264 |
